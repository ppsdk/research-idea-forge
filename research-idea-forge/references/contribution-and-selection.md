# 贡献收敛与候选选择

这是本技能的内置方法，无需先启动其他技能。参考 Supervisor-Skills 的选题审视，以及 PaperSpine 的贡献与证据契约；按用户范围作了适配。

## 一、先定位贡献，避免用动机代替创新

候选可主要表现为新问题、新方法或新设置；理论、分析、数据、系统、评估或工程优化也是合法贡献。选择一个主类型，必要时有一致的支持目标，不强行把每个方向都包装成新算法。

用一句话说明：

```text
对谁/哪种研究问题，在什么条件下，最近方法留下什么具体缺口，
我们改变哪项变量/运算/信息/约束，预期新增什么可检验能力或认识。
```

“这个领域重要”是动机；“在这些条件下增加哪种能力或知识”才是贡献。未经实测的增益是预期贡献，不能写成已经实现。

## 二、先审查能改变决定的关键问题

从实际候选找重大问题，逐项写定位、依据、影响、最小修复和状态。问题数量不设配额，也不以数目机械升级严重性。

| 关键问题 | 判断依据 | 修复或重新分类 |
|---|---|---|
| 机制与最近工作等价 | 已核验的方法步骤，而非标题相似 | 改真实运算或转复现/工程优化 |
| 目标重要性不清 | 没有具体受益者、科学问题或可观测价值 | 明确目标；基础分析不要求商业应用 |
| 主张与方法脱节 | 声称的作用没有相应步骤或关键条件 | 定位承重变量，删去无依据主张 |
| 数学/时序不成立 | 维度、可得信息、约束、依赖或推导矛盾 | 修复计算路径；无法修复则换机制 |
| 主线失焦 | 各组件对应互不相关的目标 | 保留一条贡献主线，其他内容另记 |
| 已有证据否定中央预测 | 匹配条件下真实数据与预测相反 | 收窄或改变主张，不能只改文案 |
| 无法在当前条件验证 | 明确请求开发/可行性时缺数据或资源 | 缩小试验、换证据路径、暂缓 |

**未测试不是被否定。** 缺实测不能当作逻辑硬伤。已有负结果则应先检查实现、协议、基线、随机性与适用条件；确认它确实否定核心前提后，不再宣称“多跑几轮即可成立”。可以保留为负结果、分析线索或不同机制的种子。

“从一个技术出发”也不是自动缺陷。迁移、先验和数学构建允许候选先行，随后必须找出真实目标、适用条件与差异。

## 三、五维收益是取舍工具

参考 Supervisor 的 Higher/Faster/Stronger/Cheaper/Broader，但不强制每条候选覆盖五维或都获高分。

| 方向 | 问什么 | 需要避免什么 |
|---|---|---|
| 更高 | 哪种任务质量或科学解释会改善，机制为何相关 | 只写“效果更好”或伪造提升量 |
| 更快 | 哪段端到端成本减少，质量/预算固定什么 | 只算一个模块而遗漏求导/求解/通信 |
| 更强 | 哪种扰动/分布/条件下仍成立 | 单场景成功就宣称普适鲁棒 |
| 更省 | 标签、数据、训练、部署或人工成本降低什么 | 将成本转移给隐藏环节 |
| 更广 | 保留何种结构，跨什么任务/本体或统一什么对象 | 跨领域名称相似或直接搬用充当原创 |

为候选选择一个主收益轴与必要支持轴。记录依据是实测、机制论证、提案还是未知；它们不能混为证据等级。五维并非概念质量总分，也不等于贡献越多越好。

用户没有要求评分时，用定性比较即可。需要数字时先确定所评对象与共同口径，适用维度标为 1–10 并给具体依据，缺信息/不适用标“未评估”。机制论证可支持较高潜力判断，但必须标为未实证；资源不全不压低概念分。不要套上游默认 5 分、固定接受阈值或以维度个数决定发表潜力。

## 四、重大问题与假设探针

仅在有助于候选时问：

- 哪条历史假设仍被沿用，但在目标条件下已经不必要？
- 哪种真实失败、评价盲点或基础科学问题被现有设定掩盖？
- 新技术/信息/计算条件是否改变了问题可解性？
- 若成功，改变哪类研究或使用者的决策？

这些问题产生新的切入点，不证明已经形成范式改变；渐进式但有实质价值的贡献仍可保留。

## 五、把候选整理成贡献契约

借鉴 PaperSpine 的核心贡献、必要性、设计响应与边界，在现有 idea 卡中记录实际需要的内容，不要求另建 `confirmed_contribution.md`。

| 项 | 要写清楚的决定 |
|---|---|
| 主贡献 | 一个具体、可检验的预期新增能力或认识 |
| 类型与受益者 | 方法/理论/分析/系统等；谁因此获得什么 |
| 领域问题 | 为什么当前目标重要 |
| 具体缺口 | 最近工作仍缺什么，不止“研究不足” |
| 关键难点 | 哪个技术或知识障碍使缺口尚未解决 |
| 最近工作残余 | 具体方法/假设为什么尚不覆盖此候选；未核验就标明 |
| 设计响应 | 方法如何改变承重变量并对应关键难点 |
| 所需证据 | 什么结果/证明/观察能支持或否定中央主张 |
| 现有证据 | 实际来源或结果，含协议和定位；没有实测如实写 |
| 缺失证据 | 最关键的未知是什么，哪些当前结论仍不能写 |
| 可说的主张 | 当前证据真正支持什么；有支持时不故意过度含糊 |
| 需限制的主张 | 机制、泛化、安全、效率等尚不支持的范围 |
| 新颖性/重要性风险 | 已核验重叠或实质价值问题，附最小修复 |

对于构思期，用“拟检验贡献”或“贡献假说”。证据不足限制已建立结论，不自动否定候选价值。

遵循用户已有主贡献与明确选择；新证据改变方向时只处理受影响部分。只有真实未决选择才需要用户决策，普通推导、局部改进或文件更新不重复审批。

## 六、证据对应主张

对每个中央主张标明科学用途、所需或已有证据、比较条件、允许解释和不允许解释。举例：

```text
主张：状态匹配的反馈校正，而非额外容量，是作用来源。
所需证据：同容量/数据/预算下，对照破坏反馈与状态的对应。
现有证据：仅给出整体方法增益；没有机制隔离。
允许解释：整体系统在已测条件下改善了结果。
当前不允许：校正模块已被因果证明；跨本体或物理安全保证。
```

示例为方法说明，不含真实实验。保留有效负结果、失败类别与分母；不能为贡献“好看”删除。计划、数字表、校验脚本通过或工作台状态不是证据完成。

## 七、候选比较和决定

覆盖用户要求的全部候选，用相同目标、设置、证据和范围比较：

```text
候选 | 主贡献/类型 | 主收益轴 | 运算级差异 | 最近工作覆盖
| 承重假设/重大问题 | 证据状态 | 概念价值与潜力 | 判断置信度
| 当前状态 | 最小修复或下一步
```

概念质量、发展潜力、置信度与资源可行性分开。选一条最有依据的主线及必要备选，不以未经验证的收益或“更容易发论文”排名。

明确要求可行性/发展计划时才加入数据、技能、时间和竞争窗口。参考 Supervisor 的资源匹配思路，但不用固定 3–6 月生命周期、GPU 数量或周工时推断用户适不适合；按真实条件估算并声明未知。机会窗口需要当前检索依据，不能从研究类别直接给截止日期。

最终选择可以是推进、定向修复、缩小范围、机制重构、暂缓或停止。由本技能回填并维护同一份 idea 卡，不把选题结果强制交给另一技能。
