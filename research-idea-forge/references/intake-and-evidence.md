# 入口、研究契约与证据

## 一、按决策恢复上下文

先识别用户实际需要：探索方向、开发已给候选、解释异常、比较概念、数学建模，还是实现验证。不要因为材料是论文 PDF 就转成论文完整性评审。用户要“先判断再改进”时，分别完成判断与开发，复用同一候选。

| 项 | 需要辨明的内容 |
|---|---|
| 目标 | 谁需要哪种能力，优化或解释什么量 |
| 入口 | 已有问题、可迁移机制、可用先验、数学结构、固定选择或异常 |
| 贡献类型 | 方法、理论、分析、系统、数据、评估或工程优化 |
| 锚点 | 指定文献、方法、代码、数据、异常或约束 |
| 已有证据 | 已测结果、用户报告、原始日志、公开方法、猜测分别是什么 |
| 范围 | 要多少候选、是否评分、是否给实验/实现方案、是否允许执行 |
| 资源 | 硬件、数据、模拟器、技能、时间和费用；未声明项明确未知 |
| 成功/停止 | 哪种发现改变决定，什么条件使候选收窄或暂缓 |

没有研究锚点时先收窄到一个任务、属性、目标或机制；提供少量有含义的切入点供选择，不直接声称新颖。

## 二、缺口处理

- 必需：会改变方法合法性，例如推理时是否能得到接触状态。无法核验时保留为分支条件或提出具体问题。
- 暂可缺失：完整数据规模、最终预算或目标会议；概念构建可以继续，但不要编造数值。
- 安全假设：用户已说明的研究方向和格式；普通工作流程选项可自行决定并简单说明。

局部缺口不能阻止独立工作。部署信息未知时，可完成来源核验和条件性数学推导，但不承诺闭环成立。仅概念审视无需实验材料。需要额外费用或不可逆行动时，先完成本地可审阅方案，再依权限处理。

## 三、具身研究的最小设置

- 本体：自由度、执行器和控制接口；缺材料时使用抽象接口并标明。
- 观测：图像、语言、本体状态、历史、预处理及缺失模态。
- 动作：坐标系、连续/离散、绝对/增量、单步/chunk、约束。
- 时序：控制周期、规划范围、采样时刻、反馈延迟。
- 任务/环境：对象、分布、重置、成功/超时与安全边界。
- 信息边界：训练可用、模拟器专有、oracle、执行后或未来信息。
- 迁移边界：跨任务、跨本体、sim-to-real 的哪项假设被改变。

目标接口不明确时，不把某种动作表示强加给所有问题。概念评估不扩展成完整实验协议。

## 四、证据分类与溯源

| 类型 | 用法 |
|---|---|
| 已核验公开证据 | 实际打开的方法/结果/代码，附稳定来源与位置 |
| 用户报告 | 说明是否检查原始数据与协议 |
| 推断 | 关键推理与可能的替代解释 |
| 提案 | 新方法、预测、实验和预算估算保持待验证口径 |
| 未核验/不可访问 | 记录检索或访问边界，不将其当成反证 |

同一张成功率表不能独自完成结果记录、机理解释和创新性判定。文件名、checksum、编译成功和文献登记不是科学证据核验。

## 五、可复用文献卡

在现有文献记录中维护需要的字段，不每轮复制全语料：

```text
来源身份与版本：题名、作者、发表/预印本状态、链接、访问日期
实际阅读范围：全文方法 / 官方代码 / 摘要 / 不可访问
问题与条件：任务、数据、部署信息和关键假设
方法原语：表示、目标、约束、算子、监督与更新
证据与边界：主实验、对照、负面结果、成本和不能推出的结论
定位：章节/公式/页码/代码路径
作用：支持、冲突、迁移来源、直接竞争或待查
```

核验论文身份后还要核验引用语境。近期研究、软件或版本敏感结果要刷新；不受变化影响的已核验材料复用。

## 六、检索边界

优先主来源、官方代码和权威记录。不要向外部查询复制私有未发表的独特句子；用抽象公开术语。学术检索不足时使用普通搜索、公开索引或官方页面，并写覆盖限制。

用户禁止检索时继续内部建模和条件性方案，不声称验证创新。只给几篇文献时，说明结论是否限于所给集合。
