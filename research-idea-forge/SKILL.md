# 科研创新点构建：迁移与数学重构

把方向、已有方法、结构先验或经验异常转成可讨论的科研候选：问题或机会明确，机制可解释，数学改变实际运算，与最近工作存在可核验的差异，并知道怎样推翻关键假设。核心方法是**多入口构思，再共同收敛**。机制迁移与数学重构是重点工具，不是每个任务必须经历的阶段。

默认用中文解释，保留技术术语。从用户当前要作的决定开始；短任务交付局部改进，完整开发才交付完整 idea 卡。

## 适用范围与主责

- 发现、锐化、救活或开发候选：本技能可独立完成构思、检索核验、候选审视、贡献收敛和最终 idea 卡，并负责后续修订；无需先调用 `ccf-idea-optimizer`。
- 本构思流程中的候选比较与概念审视由本技能完成。用户明确选择本技能做纯概念判断时，也可直接完成，保持无实验/资源评估的范围；单独概念评审未指定技能时遵循已有评审路由。
- 用户明确选择 CCFA 流程，或项目已声明 CCFA 的 idea 主责时，尊重该主责，本技能作方法支持。仅“装了 CCFA”不构成归属依据；不要同时设两个主产物负责人。
- 为当前 idea 检索文献可由本技能使用现有工具完成；单独文献综述、正文、完整实验协议、运行实验、图表或投稿只有属于请求范围时才交给相应技能。
- 缺少其他技能时，直接用本技能和可用工具完成授权范围，说明实质能力缺口；不要声称未运行的技能、独立审稿或实验已经完成。
- 本技能可自然触发或通过 `$research-idea-forge` 明确调用。普通代码问题、单篇论文摘要、单纯论文润色不自动进入完整构思流程。

优先遵守当前请求、具体项目规则和用户研究伴随规则。已有明确主产物不复制；默认在同一份 idea 卡中更新。`idea-spark`、Supervisor-Skills、PaperSpine 和 CCFA 按需辅助，不是本技能运行的前置依赖。

| 把问题数学化、用数学寻找创新 | 从目标/约束构建数学对象，推导可执行算子与判别性预测 | [数学问题构建](references/mathematical-construction.md) |

## 不可省略的区分

1. **已核验证据、推断、提案、缺失信息分别标明。** 检索空白或打不开全文不证明“无人做过”。
2. 机制新颖性来自变量、目标、约束、运算、信息或接口的实质变化；新名字、换领域、模块叠加、公式变长都不是充分理由。
3. 可先转移、加先验、替换算子或做小原型，再回头解释机制；不强制先定位瓶颈，也不强制生成“原生/迁移/组合”三套候选。
4. 数学必须改变算法、揭示条件、产生可检验预测、提供求解方式或给出条件性结论。符号重写不能自动升级成理论贡献。
5. 文献结论要搜索并核验具体来源。若用户禁止检索，做条件性构建并写“新颖性未核验”；不要暗示完成碰撞审查。
6. 小数值检验只能支持计算自洽；原型或基准提升不能独自证明因果机制、泛化或理论保证。
7. 概念评审不因未做实验、未有预算或未写代码扣概念分。可行性和实证充分性只有在请求范围内才另行判断。
8. 采用用户资源约束。不要导入辅助技能的默认大 GPU/API 预算；不把未来帧、oracle、模拟器真值或额外标签默认为部署时可用。

## 构建与收敛

### 1. 恢复研究契约

从对话、当前材料和工程上下文确定：决策、目标、贡献类型、入口、已知最近工作、资源和明确限制。区分必需未知、可先搁置未知和安全假设；只询问会改变路线且无法自行查明的缺口，同时完成不依赖回答的工作。

具身任务要明确本体、观测/动作、时序、任务/环境、部署信息、安全及 sim-to-real 边界。仅构思时不以缺少实验文件阻塞工作。细则见 [入口与证据](references/intake-and-evidence.md)。

### 2. 选择自然入口并形成候选

可从科学问题重构、机制迁移、数学问题构建、先验注入、机制组合、质量成本优化、固定选择解放、算子替换或经验异常进入。

先写一句可检查的机制句：

> 在条件 S 下，改变变量/算子/接口 X，使计算或信息路径 Y 改变，因此预期下游量 Z 沿某方向变化；条件 F 会使这个预测失效。

没有真实数据时这是假设。候选数量服从请求与问题，而非配额；多个候选使用共同目标和比较条件，主线只保留一个核心机制及必要支持组件。

### 3. 用文献收窄差异

覆盖直接邻居、同机制异名、来源机制、基础工作、近期工作和诊断/负面证据。按假设、表示、运算、监督与部署信息比较，不只按标题或发表时间归类。最近工作的关键方法需要阅读全文或官方代码；只有摘要时限制差异结论。

已有文献记录不重复复制。新增来源、未能访问部分和会改变决定的分歧，写入所属文献记录。参见 [新颖性与一致性](references/novelty-and-coherence.md)。

### 4. 完成入口契约

- **迁移：** 源机制 → 目标结构 → 映射 → 保留属性 → 必要适配 → 目标最近工作差异 → 朴素迁移与破坏映射的控制。
- **数学：** 决策对象/信息集 → 目标/约束 → 可辨识假设 → 建模 → 推导 → 符号到实现 → 退化与复杂度 → 检验性预测。
- **先验：** 先验来源、计算插入点、构造保证与学习部分、错误先验条件及对照。
- **组合：** 各部分处理不同职责，必要接口可命名；打乱/延迟/断开接口后应损失何种作用。
- **优化：** 主质量或成本目标、固定预算、匹配基线、全路径成本和成本转移。

只完成适用契约；不为流程完整性硬造不相关内容。

### 5. 检查自洽并提出最小区分实验

逐步追踪输入、输出、尺寸、信息可用时间、训练/推理、梯度和依赖。新数值算子在合适时做小实例与相关边界检验；公开条件不够则保持条件性结论。

完整机制开发要给出：一个承重变量、一个下游指标及方向、一个破坏机制而尽量保留预算/容量的对照，以及何种结果使主张被否定或收窄。这是**计划**，除非实际执行并有日志。参见 [验证与可行性](references/validation-and-feasibility.md)。

### 6. 决定状态并交付

先区分问题、方法或设置创新，再按实际需要审视五维收益和可能否定中央主张的问题。用“重要问题—最近工作留下的具体缺口—关键难点—方法响应—主贡献”收敛；写出需要什么证据、已有多少证据、当前能说什么。详见 [贡献与候选选择](references/contribution-and-selection.md)。

共同检查目标、机制、新颖性、自洽、可证伪、可行性、主张对齐和入口有效性；相关项标为“已规定 / 有依据 / 失败 / 未核验”。不要把方案描述当作实证通过。

候选状态可为：论文级开发候选、探索种子、工程优化、分析线索、基线/消融资产或暂缓假设。论文级候选只表示值得开发，尚不证明有效或可投稿。失败候选保留有用部分，写出最小修复；同一硬问题两次定向修复仍失败时停止推广该主张，转为收窄、重构或暂缓。

输出与用户范围对应，见 [输出与协作](references/output-and-routing.md)。完整 idea 卡可使用 [中文模板](assets/idea-card.zh.md)，局部请求只更新受影响字段。

## 辅助方法的使用

- `idea-spark`：当深检索、模式库、碰撞、自洽或可实现性审查有实际增益时调用。其具体运行契约在真正执行时适用；若该运行方式与用户多入口选择冲突，使用可兼容的方法参考或本技能工具，不声称完整 pipeline 已运行。
- Supervisor-Skills：本技能已吸收五维收益、问题/方法/设置定位、致命问题与修复、隐含假设探针，并按需采用资源/生命周期匹配。额外深调研或外部概念审视确有增益时再调用，不默认另跑一套评分。
- `paper-spine`：本技能已吸收主贡献、重要性、具体缺口、设计响应、证据与边界的方法。读参考方法不等于启动 Web 工作台；完整论文生产才适用其完整协议。
- 不因拥有这些技能而全部调用；缺少辅助技能时本技能仍可用。自动监控、付费 API、大规模实验和外部提交不由本技能的文本自动授权。

## 完成标准

本技能交付并维护所请求的 idea 卡、候选比较或局部判断。候选有目标、运算级变化、具体贡献、证据状态、最近工作差异或未核验边界、关键假设及下一步判别方法。迁移需说明保留结构，数学需落到可计算步骤。准确报告未检索、未执行和未解决内容，不给创新或发表保证。
